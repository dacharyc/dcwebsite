Here's what I'm thinking about this week in agent experience land: eval design is a hard problem!

I've learned a ton about it over the last year, largely by reading prolifically anything I can get my hands on and trying things myself. I read a lot of research papers' methodologies and dig into public repos. I run my own evals, see where they can be improved, and build better next time. 

From what I've seen, I can only draw the conclusion that most people are running flawed evals.

Not because we're not careful, or thoughtful, or aren't *trying* to do things right... but because to run a good eval with a solid methodology is a lot of work and it requires a lot of domain knowledge.

But this matters a lot when you're trying to make your product better for agents... because the only way you can *really* do this is by running evals. Otherwise you're taking a shot in the dark by taking some action based on the latest podcast, blog post, or viral "do this one thing" sound byte, and you never know if you had that problem to begin with or if the change you're vibing makes things better or worse.

So you've gotta run evals in order to know what problems exist and whether the changes you make improve them. But evals are hard to design and run in a way that doesn't carry flaws that make them next to useless.

And no, agents can't design your evals. You need to have the judgment required to make decisions and guide the process. I am seeing this manifest in so many different types of problems that I've started keeping an "Eval Pitfalls Checklist" and am trying to figure out the best way to make that actionable.

Hard problems are still hard, happy Wednesday.
